## 真实 ABI 和观测位置

冻结 MRV2 的 FULL 路径是 `CudaGraphManager.run_fullgraph -> self.graphs[desc].replay()`；
`torch_cuda_wrapper` 将 CUDAGraph 映射为 NPUGraph。v1 的 `ACLGraphWrapper/entry.aclgraph` 不在这条路径。
因此只为此 manager 的 graph 实例安装代理，原 replay 原样调用一次，原异常继续传播。
不复制 core execute/sample/capture 实现、不修改 core，不关闭编译或 FULL graph。

| 位置 | 新观测 | 可信性/限制 |
|---|---|---|
| `DeepseekV4Model` 构造 | 显式 opt-in 时分配 layer banks 并绑定各层 | 在首次 compile/profile 前存在，不依赖后装 Python hook |
| 每层真实 forward | attention 输入/输出、HC residual、FFN 输入/输出、层输出 `copy_` | 编译进 target，随后记录进 FULL graph；保存独立内容，非 live view |
| 模型输入及尾部 | embedding、pre-HC、post-HC、post-norm | 同轮首个异常的已观测边界；尚未分开 HC pre/norm、attention 内部、MoE 内部和通信 |
| `ModelWithContext` 返回前 | raw hidden/aux 写入独立 source 快照 | 在 core 持久 hidden/aux copy 前执行，保留 copy 源的当轮内容 |
| 实际 NPUGraph replay 前 | 输入/metadata 当前内容、captured 引用内容及布局 | 已完成 prepare_inputs、gather/slots、prepare_attn 和 core offloader sync；不是 execute 入口 |
| 原 replay 返回后 | 层快照、raw source/持久 destination、pre-HC source/destination | 同一 current stream 上检查，D2H 等待前面的 graph 写入；尚未返回给 sample/propose |

每个 layer bank 的每个边界都有独立的设备 epoch receipt，raw output 另有 receipt。
replay 前先清除当前 shape 的 receipt，再填入本轮 epoch；graph 内仅用 device `copy_` 发布 receipt。
必须是所有边界的 receipt 与当前 epoch 一致，且原 replay 已返回，才标记 `ACTUAL_FULL_REPLAY_SNAPSHOTS`。
capture 数值、空 replay、遗漏编译节点和执行异常都不能冒充本轮观测。

`residual` 不是普通二维 hidden：该模型在 HC attention post 后 clone 出 `[tokens,hc_mult,hidden]`，
再送入 FFN HC post；层最终返回 `(hidden_states, residual)`。
快照分别保留 residual 和层输出，且位于后续原地操作之前。
FFN、attention 等输入/输出是 `[tokens,hidden]`，不是假设所有模块只返回一个相同形状的 tensor。

core 在 capture closure 中将 raw model output copy 到最大 shape 的持久 hidden/aux，replay 返回 prefix。
原 raw tensor 的生命期属于 compiled/capture graph pool，R9 只记录原布局，不额外强持其 live tensor。
R9 强持的是独立 source 快照；captured 输入引用本来就由 runner 持久 input buffer 拥有。
跨 shape 共用 pool、相同地址或 weak-ref workspace 均不能单独判错。
`different_rows` 比较同轮 copy 前源快照与 copy 后目标内容；NaN 对 NaN 仅在这个比较中视为相同，
有限性仍判失败，绝不改写 NaN 或有效 KV。

## replay 前输入与 metadata

记录实际 input_ids、positions、device query offsets、seq_lens、is_padding，以及它们的
shape/stride/storage_offset/data_ptr/storage_data_ptr/device/dtype。
request 映射同时核对 runner row、device/CPU idx_mapping 和 req_states.req_id_to_index；
query span 与本轮 scheduler request/token 数对照，不以旧 UUID 定位。

- query offsets 与 CPU 预期逐项比较；seq_lens 的 CPU 字段是**上界**，只检查该关系，不误当成精确真值。
- positions 与本轮 device seq_lens/query span 核对；captured input 引用的有效内容与 current buffer 比较。
- 异步生成的 sampled/draft input_ids 没有本 ABI 可直接提供的完整 CPU 真值，明确标为 unavailable；
  实际 device IDs 仍保存。有限性/metadata 相等不等于完整 token 正确性证明。
- 每个实际 KV group 保存真实 block_size/kernel_block_size；使用本轮 request-state `num_blocks.np`
  限制 block table 读取列数，比较 request-state device 表、gathered 表和 captured metadata 表。
  不读取未分配表尾；slot 映射按有效 positions/真实 kernel block_size 核对，padding 只接受精确 `-1`。
- DSA decode/prefill 的 query/seq/positions/start_pos、slot、SAS/QLI、sin/cos 分别记录来源、布局和有效内容或有限性。
  共享 metadata 用 owner/ref 表达。full compressor RoPE 表只记布局，不 dump 全表；graph 内生成的
  compressor/topk 读取范围仍 unavailable，不扫描 target KV 容量，也不把未初始化容量当 NaN。
- DSA 的 `update_graph_params` 实际是 no-op，没有需更新的 DSA task/handle；
  本路径依赖 prepare_attn 的持久 tensor copy。报告当前 stream ID、源码依赖顺序及 reshape event 身份；
  不伪造 event 完成状态，不更改现有 stream/event 顺序。

## 开关、开销与窗口

默认关闭：只有同时提供 `--dspark-nan-diagnostic-dir` 和新增
`--dspark-nan-replay-window FIRST LAST` 才启用 R9。仅 R8 directory 开关保持原有 R8 行为。
关闭 R9 时没有 layer snapshot 分配、额外 graph 节点、hook 或新增 D2H/同步；draft 层始终不绑定 target bank。

首次窗口为 **60–80（含端点）**，只控制详细读取/落盘，不改变被捕获的 graph 节点。
各 graph 持续写入按 shape/layer/rank 隔离的预分配 bank，compiled model 用 shape 推导相应 slice。
截断长度使用显式 `torch.sym_min`；不能读取 profile 截断张量的长度来选 bucket，
否则 Dynamo 可能将其固定为最大 shape，而冻结 core 的无 guard 调用不会触发重新编译。
当前实现明确要求连续 uniform-query capture buckets；本例 `[6,12,18,24]`。
profile/eager 也可能执行同一编译模型中的有界 copy，但这些值不会被作为 FULL replay 证据读取。
FULL receipt 新鲜度及实际调用入口共同限定观测来源。

按 43 层、hidden=4096、HC=4、BF16 计算：262 个 layer/模型边界，层 bank 与 receipt 合计
**257,069,156 bytes ≈245.16 MiB/rank**，另加约 1.88 MiB/rank 的 raw output banks 和 receipt。
每次 graph 新增 524 个 layer 内容/receipt `copy_` 与 5 个 raw output/receipt `copy_`（源程序操作数，非编译后 kernel 数）。
每轮读取的有限性只向 CPU 传逐行 NaN/+Inf/-Inf flags；所有 layer flags 合并一次 D2H，
输入、metadata、receipt、source/destination 比较另有有界 D2H/同步。
不把设备统计算子放进 capture；copy_ 采用与已有持久输出 copy 相同的 ATen 路径，无新 custom op。
本地仅验证 CPU Torch 流程，NPU 编译、int32 receipt copy 的 capture、内存池和 stream 行为仍须实机验证。

层 bank 在 KV profile 前分配，可能改变 KV 容量和内存布局；诊断 copy 与 D2H 也可能改变异步时序。
即使本轮故障消失，也只能报告“未复现，可能受观测扰动影响”。**performance_eligible 永远为 false**。
不在同一可写 KV 上追加 eager forward，不运行 exact-token correctness 项目或性能矩阵。

## 产物与判读

- `rank-*-first-failure.json`：首次异常只写一次。优先看它，而非后续 ownership 异常。
- `rank-*-latest.json`：保留外层异常传播；history 最多前两轮，epoch/request 各自独立。
- `rank-*-window.json`：最后一个详细窗口轮次及前两轮，窗口结束后继续生成也不会丢掉这组观测。
- `diagnostic-index.json`：分别报告 generation_status、diagnostic_evidence_status、localization_status。
  收齐八份文件不是定位成功；当前或前两轮详细观测不足时会报 COVERAGE_INSUFFICIENT。

首错主要字段：

```text
current.target_execution_epoch / phase / request_ids
current.replay_detail.graph_shape / graph_object_id / replay_epoch_receipt
current.replay_detail.pre_replay.request_mapping / mismatches / unavailable
current.replay_detail.boundaries.<name>.{nan,positive_inf,negative_inf}_rows
current.replay_detail.localization.last_finite_boundary / first_invalid_boundary
current.replay_detail.output_transfers.<name>.source / destination / different_rows
previous_executions
```

`OBSERVED_BOUNDARY_BRACKET` 只表示相邻已观测边界，不能直接命名内部 kernel 为根因。
窗口未命中、receipt 缺失或 replay 异常均明确 unavailable，不从 capture/config 猜测补齐。
完整生成结束时仍要求 1024 measured tokens、TP8 每 rank measured FULL replay > 0 和实际 24-token shape；
满足后标 `NOT_REPRODUCED_OBSERVER_MAY_PERTURB`，不会发布性能通过标记。
