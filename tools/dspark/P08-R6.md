对照冻结 core 的实际调用链：

| 边界 | 冻结实现及结论 |
| --- | --- |
| public LLM → LLMEngine → SyncMPClient | `collective_rpc(method, timeout, args, kwargs)` 原样传递 method |
| frontend → EngineCore | `SyncMPClient.call_utility` 构造 `(0, call_id, "collective_rpc", args)`；`_send_input` 调用 `MsgpackEncoder.encode` |
| Msgpack 编码 | `v1/serial_utils.py::MsgpackEncoder.enc_hook` 在 `VLLM_ALLOW_INSECURE_SERIALIZATION` 未设置或为 0 时拒绝 function；executor 尚未收到请求 |
| worker extension 注册 | `EngineArgs.worker_extension_cls` 进入 ParallelConfig；`WorkerWrapperBase.init_worker` 用 `resolve_obj_by_qualname` 导入类、检查命名冲突，并将其加入实际 worker class 的 bases |
| EngineCore → executor → worker | `MultiprocExecutor.collective_rpc` 直接广播字符串方法名；`WorkerProc.worker_busy_loop` 对 worker wrapper 执行 `getattr`，wrapper 再转发到真实 worker |
| 返回 frontend | `UtilityResult` 在安全序列化模式下携带基础数据；本次结果不需要 pickle 或类型重建 |

executor 虽然另有 callable/cloudpickle 分支，但它位于本次失败边界之后，不能用它证明 frontend 接受函数。

## 修改范围与保留的验收条件

将查询移到可通过已安装 plugin 路径导入的专用模块：
`vllm_ascend.diagnostics.dspark_benchmark_worker.DSparkBenchmarkWorkerExtension`。
benchmark 在 graph 模式构造 LLM 时显式传入 `worker_extension_cls`，
随后调用 `collective_rpc("dspark_benchmark_graph_runtime")`。
extension 只有只读查询方法，没有初始化、模型执行或采样 override。
不依赖脚本的 `__main__`、frontend 内存中的函数或 `tools` 目录的 worker PYTHONPATH。
eager benchmark 不注册该 extension。

返回值只包含 dict/list/str/int/bool/None。NumPy integral rank/size 转为 Python int，
mode enum 转为字符串；graph 对象仅用于本地读取 descriptor，不作为返回值。
非法 rank、descriptor size 或非 bool flag 会明确失败，避免意外返回设备 tensor。
frontend 检查 TP8 rank 完整且唯一，保留各 rank 的实际 capture 数、配置/观察到的 sizes、
target FULL_DECODE_ONLY、drafter NONE，以及 Ascend graph flags 的一致性检查。
显式请求 capture sizes 时，还要求 worker 配置和实际捕获集合与请求相符。

warmup snapshot → collector reset → measured generate → measured snapshot 的流程不变。
正式生成必须发布 FULL replay；capture 或 warmup 成功不能替代它。
没有关闭 graph、开启 pickle fallback、添加跨模式 exact-token 条件或修改 R5 的校验/同步行为。
core、attention、custom op、worker/model runner 和 DSpark 计算路径均未修改；R1–R5 保持原样。

  分别测试 `VLLM_ALLOW_INSECURE_SERIALIZATION` 未设置和为 0。
  执行冻结 core 的 LLM/LLMEngine/SyncMPClient、Msgpack encoder/decoder、utility result、
  worker extension 注入、executor 和 worker busy-loop 的真实源码函数体。
  编码消息进入全新的 Python 进程，按 benchmark 的实际 engine kwargs 导入并注册 extension，
  查询 8 个 CPU worker fixture 后返回并解码。旧 callable 在发送前复现 TypeError；
  只改字符串而不注册 extension 的情况明确失败。

## 服务器一键 Graph P1

在原已初始化 CANN/custom-op 的容器中使用
[run_p08_r6.sh](run_p08_r6.sh)。第一个参数必须是本次交付的完整 40 位 plugin commit SHA；
core SHA 固定在脚本中。脚本会打印 expected/actual SHA，要求 checkout 干净并精确相等；
缺参数、SHA 不符或导入路径不符都在 SOURCE gate 停止，保留失败日志。
执行模板如下；最终交付消息提供已填入 SHA 的命令：

```bash
git -C /workspace/vllm-ascend-hust pull --ff-only origin feat/dspark &&
    bash /workspace/vllm-ascend-hust/tools/dspark/run_p08_r6.sh "$P08_R6_SHA"
```

固定 TP8/EP、K=5、B=1、capture sizes=[6]、target FULL_DECODE_ONLY、drafter eager，
显式设置 `VLLM_ALLOW_INSECURE_SERIALIZATION=0`，沿用 R5 脚本的模型、dataset 路径和固定数据 SHA256。
每次新建 `/workspace/dspark-results/m2_5a-p08-r6.XXXXXX`，保存脚本、版本/extension 导入路径、
数据副本、日志/JSON、各管道 PIPESTATUS、gate 和执行后快照；不删除旧目录或失败产物。
不用 `set -e` 或 shell `exit`，管道后立即保存 PIPESTATUS，以 return 阻止依赖步骤继续。

JSON gate 要求实际 capture、**正式生成 measured FULL replay > 0**、正式 verification 的
padded/unpadded query tokens 均为 6、真实 drafts > 0，并完成 engine shutdown。
本轮只执行 Graph P1；通过后再进行 B=2/4 小 batch，然后做同配置 eager/graph 性能比较。
无需 `build_aclnn.sh`。
