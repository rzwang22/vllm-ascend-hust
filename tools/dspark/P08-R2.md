## 冻结 core 与调用点审计

core `vllm/v1/worker/gpu/cudagraph_utils.py::ModelCudaGraphManager.capture` 的七个必选参数为
model、model_state、input_buffers、intermediate_tensors、block_tables、attn_groups、kv_cache_config。
之后依次为：

```python
has_lora: bool = False,
use_aux_hidden_state_outputs: bool = False,
lora_capture_hook: Callable[[int, int, int], None] | None = None,
progress_bar_desc: str = "Capturing CUDA graphs",
```

返回值为 `dict[BatchExecutionDescriptor, AttentionStatePair]`，每项保留 warmup/captured attention state。
父类在准备每个 capture descriptor 的 forward 时调用 hook，并自行处理 aux hidden states。
旧插件除了缺少 hook 参数，还把 progress 文本按位置传进了父类的 hook 槽位。

- target：插件 `worker/v2/model_runner.py` 安装 `ModelAclGraphManager`；继承的 core
  `GPUModelRunner.capture_model()` 按关键字传入 has_lora、aux flag、hook，随后将返回的
  attention states 传给 speculator。插件内没有另一处使用该 target capture 的可选位置参数。
- Eagle：`worker/v2/spec_decode/eagle/aclgraph.py` 的 prefill/decode manager 分别继承 core
  `spec_decode/autoregressive/cudagraph_utils.py` 中的两个 manager。它们各自的 capture
  签名没有 LoRA hook，末尾仍是 progress 文本，原转发没有错位，不需修改。
- DSpark：`worker/v2/spec_decode/dspark/speculator.py::capture(attn_states)` 仍为 eager no-op，
  接收 target attention states 的接口未变。R1 loader、配置构造及 draft forward/profile 均未改动。

K=5 时 target verification query length 为 `5 + 1 = 6`；P1 明确设置 capture sizes `[6]`。
旧 `[1,2,4]` 不覆盖该 shape，属于后续 replay 覆盖问题，不能替代本次接口首错。
