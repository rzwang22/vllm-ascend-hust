## 完整消费链与 kernel 语义

| 层次 | 冻结源码行为 |
| --- | --- |
| AscendBlockTables | `worker/v2/block_table.py` 重新分配 int32 常驻 `slot_mappings`，继承 core 的 dummy getter |
| core dummy | `v1/worker/gpu/block_table.py::get_dummy_slot_mappings` 对整个 buffer `fill_(PAD_SLOT_ID)`，返回原地址上的切片；PAD_SLOT_ID 为 -1 |
| 真实更新 | Ascend `compute_slot_mappings` 的 Triton kernel 写入有效 slot，并将尾部 padding / CP 非本地位置写为 -1 |
| formatter | non-A5 `BaseDeviceAdaptor.format_dsa_slot_mapping` 对 flat slot 做整除和余数；block_size=32 时 -1 变为 [-1,31] |
| metadata | DSA `build` 将格式化结果复制进 builder 的常驻 `slot_mapping`；SWA decode metadata 持有其切片 view，non-A5 padding helper 不替换该 view |
| forward | DSA SWA `_forward_decode` / `_forward_prefill` 的 shared-KV page validator 检查 metadata，随后 `dsa_kv_compress_scatter` 调用 `torch.ops._C_ascend.npu_scatter_nd_update_v2` |
| C++ binding | `csrc/torch_binding.cpp` 将实际 `var.strides()` 转交 `aclnnScatterNdUpdateV2` |
| tiling | `csrc/moe/scatter_nd_update_v2/op_host/scatter_nd_update_v2_tiling.cpp` 用实际 strides 构造 indicesMask，并按物理元素范围选择排序分支 |

当前契约强制 slot 为 int32 `[T,2]`，故实际 dispatcher 使用 int32 key 10 或 11，
不能用只属于 int64 large-index 的 key 30 推断这次行为。
host 以索引维度（这里为前两维）的 `sum((shape[i]-1)*stride[i]) + scatterLength` 计算物理范围；
不超过 `(1<<24)-1` 元素时 key 11，否则 key 10。
证据没有给出失败层 SWA tensor 的实际 shape/stride 或 tiling key，而且先在 validator 失败，
不能声称该次已执行某个 scatter key。日志的总 KV token 容量也不能替代 hybrid SWA tensor 大小。
本次审计并在 CPU 执行了两个可能的 int32 分支的地址与边界逻辑。

page validator 原有约束保证 `[N,B,H,D]` 的 dense page-local strides 为 `[BHD,HD,D,1]`。
`LinearIndexKernel::Compute4LinearIndex` 将索引按这些 strides 加权，
因此精确 sentinel `[-1,B-1]` 的线性地址是 `-BHD+(B-1)HD=-HD`。

- key 10：`LinearIndexKernel<false,int>` 后接 `ScatterNdUpdateV2KernelNoSort`，
  仅对 `start_ <= linearIndex < end_` 执行写入；所有 core 的写范围非负，sentinel 被跳过。
- key 11：`LinearIndexKernel<true,int>` 后接排序 kernel，
  `findFirstLt` / `findLastGe` / `UpdateSearchParam` 只选取 `[start_,end_)` 内的索引；
  负地址不进入写入区间，全 dummy 时无有效边界，不写 KV。

这两个分支都允许该占位，不需要 clamp 到 block 0，也不需要改 custom op。
任意其他负 slot 都不能借用这个例外；例如 flat -2 对应 [-1,30]，仍明确失败。
[-1,32] 虽可能在线性化后别名到真实 KV，也必须失败。
真实越界 block、非法 offset、block table、page stride/storage、device/dtype、请求和 query 校验继续保留。
A5 的 flat slot 及其 scatter 实现、其他 attention backend 均未修改。

## warmup、capture 与 replay 状态

冻结 core 对 FULL warmup 和实际 capture 分别调用 `prepare_inputs_to_capture()`，
两次均传 `CUDAGraphMode.NONE`、`for_capture=True`；NONE 不能用来排除 capture warmup。
R3 路由继续为每次构造创建新的三组共享 metadata 字典，调用 DSA 专用 capture builder。
metadata 对象及其 `sharedkv_contract_validated` 标记每轮重新创建，builder tensor 的地址持续复用。
本次 sentinel 判断不依赖 runtime mode，也不复用上一轮布尔校验结果。

正常 metadata 构造随后将真实 slots 原地复制到同一 buffer；已捕获的 tensor view 通过同一地址
读到更新内容。再次 dummy 准备会清除先前有效 slots，混合 padding 只跳过占位行。
DSA `update_graph_params` 的既有行为、copy/update 机制没有变化。
device 端仍使用原异步 tensor assertion；其真实 NPU capture/replay 执行需要服务器验证。
