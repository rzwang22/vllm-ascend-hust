## 修改与计数语义

复用 R6 已注册的 `DSparkBenchmarkWorkerExtension`，增加命名方法
`dspark_benchmark_replay_snapshot`。第一次 RPC 在模型加载/capture 完成后安装 observer；
重复 RPC 复用同一 observer 和累计计数，不重复包装，也不清零。
eager benchmark 不安装 observer，不调用 telemetry RPC。

observer 只存在于 benchmark worker 实例，包装 `execute_model` 与 target manager 的
`run_fullgraph`，各调用原方法一次，使用冻结 core 的显式参数签名并按关键字转发可选参数。
成功返回的 FULL 调用暂存到本次执行中，只有所属 `execute_model` 成功返回后才提交计数。
原方法异常直接传播，pending 记录丢弃；异常之后的调用不会继承上一轮 pending。
`dummy_run` 和 `is_profile` 显式排除；没有所属执行的 replay 单独记为 excluded。
capture 的 dummy forward 在安装前已完成，也不经过真实请求的计数分支。

本轮完成的 `execute_model_state.input_batch.num_tokens` 和 `num_tokens_after_padding`
提供实际 unpadded/padded 主机整数，并与本次 FULL descriptor 交叉检查。
不从配置、capture 数、draft 数或日志推算次数。按 token shape 聚合直方图，
`records[].count` 是该 shape 的调用次数，`record_count` 是次数总和，不是直方图行数。

三个累计快照分别位于 warmup 前、warmup 后/measured 前、measured 后。
以相邻快照差值形成两个独立阶段，保留全部原始快照、observer ID 和各 rank 证据。
拒绝 rank 缺失/重复、observer 重置/替换、计数倒退、shape 不一致或区间执行失败。
要求 TP8 各 rank 的 shape/次数一致，然后取一个 rank 的次数；不会把一次 replay 加成八次。
正式阶段 FULL replay 必须大于 0，只有 capture、dummy 或 warmup 不能通过。

每步仅增加两层 Python 调用包装，以及成功 FULL 执行后的主机整数检查和字典计数。
没有新设备同步、`.cpu()`、`.item()`、D2H 拷贝、逐层日志或每步 RPC；
快照序列化只在三个边界发生，均在正式 `generate()` 计时区间之外。
计数代表正常返回的实际 replay 调用；不额外同步设备来检测异步故障，
最终 PASS 还依赖同步 `generate()` 正常返回。实际 NPU 开销尚未测量。

FULL observer 不观察 eager/PIECEWISE 路径，fallback 明确标为 unavailable，计数为 JSON null。
summary 支持此缺失值，不伪填 0。统计验收或边界 RPC 失败时，JSON 保留 outputs、
原始 timing/throughput、acceptance 和已收到的快照，标记 `replay_evidence_status=unavailable`。
CLI 返回 1，不打印 benchmark PASS；summary 拒绝把该诊断文件作为通过结果。

R1–R6 保留；没有修改 core、attention、custom op、采样、proposal 或 KV 计算。
没有关闭 graph 或新增跨模式 exact-token 性能门槛。
